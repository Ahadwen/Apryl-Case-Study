# Apryl Case Study

Case study presentation as a browser-based JavaScript app. Plain ES modules with no build step and no dependencies, so GitHub Pages serves the repo as-is.

## Structure

- `index.html`: app shell
- `src/app.js`: slide engine (1280×720 stage scaled to fit, keyboard and button navigation, deep links via `#slide-id`)
- `src/slides/`: one module per slide, ordered in `src/slides/index.js`. Each exports `{ id, title, className?, render(el) }`; `render` builds DOM and may return a cleanup function, so a slide can be a fully interactive prototype.
- `src/styles.css`: design tokens and layout
- `prototype/`: the document upload prototype, a standalone page that is the Prototype slide (also usable on its own, e.g. on a phone)
- `wireframe.html`: the wireframe the prototype was built from
- `vendor/`: Tesseract.js 5.1.1 (OCR, with English data) and pdf.js 4.10.38, served locally so nothing loads from a CDN

## Prototype: document upload

1. The patient uploads one or more documents (photos or PDFs). They're read on the device: PDFs via their text layer, photos and scans via Tesseract OCR (`prototype/ocr.js`).
2. The patient's name and date of birth are matched against their (demo) profile, tolerant of formats and OCR slips; other identifiers (NHS/patient numbers, email, phone, postcode, street address) are caught by pattern. All are replaced with placeholders (`prototype/identifiers.js`). This happens automatically and isn't shown to the patient; the prototype shows it in a "Behind the scenes" panel beside the patient's screen, to explain the GDPR side.
3. Only that anonymised text goes to Claude, through the `claude-proxy` Edge Function, with a JSON schema so the answer always has the same shape (`prototype/extract.js`).
4. The patient first says what they're claiming for. With their country (from their account) that picks the requirements from a matrix (`RULES` in `prototype/fields.js`, assumed for now): required **documents** (invoice, proof of payment, sometimes proof of medical necessity or a prescription), ticked when a matching document is recognised, and required **details**. When medical necessity is needed the patient is told up front and given a pre-filled message to send their clinic; "Save and finish later" is a concept only.
5. Only documents that identify the patient (their name, date of birth or national ID number, e.g. a Swedish personnummer, is on them) count: details and document requirements from anonymous documents are ignored.
6. Results from all documents merge into one list (`prototype/fields.js` defines the fields, currently assumed). Each detail is confirmed or edited one by one. A missing or wrong detail can be fixed by uploading another document, or by typing it in and choosing which uploaded document shows it; typed values are flagged as manual on the claim.

Sample documents (all details invented) are in `prototype/samples/`, generated by `node scripts/make-samples.cjs`. They, and the demo patient switch, live in the behind-the-scenes panel since they are demo tools, not part of the patient's screen.

Navigate with the buttons on the left and right edges, or keys: `→` next, `←` previous, `Space` / `Shift+Space` step a blur-focus through the slide's sections (marked with `data-focus`; `Esc` or changing slide clears it), `1`–`8` jump to that numbered slide, `Home` / `End`, `f` fullscreen. Navigation keys are ignored while focus is inside an input or any element marked `data-capture-keys`. The Prototyping slide is the prototype itself, full-window (`fullBleed: true`) beside a thin context column; it loads `prototype/?inline` so all three columns share one gap; while it has focus it passes `←` / `→` and `1`–`8` back to the deck, except when the patient is typing or a dialog is open.

## Local preview

```sh
python3 -m http.server 8000   # then open http://localhost:8000
```

ES modules don't load from `file://`, so open it through a server.

## Hosting

GitHub Pages, **Settings → Pages → Source: Deploy from a branch**, branch `claude/peaceful-einstein-obqdri` (later `main`), folder `/ (root)`.

## Supabase

Shares project `vefbvrgnobfapzosivag` with the Reonic prototype; Apryl's own objects are prefixed `apryl_`.

- **Visit counter:** `supabase/migrations/0001_apryl_visits.sql` creates `apryl_visits` (per-day totals) and `apryl_visit_log` (time + browser time zone, no IP). The page calls `apryl_count_visit` on load (`src/visits.js`); localhost isn't counted. Apply it once in the Supabase SQL editor.
- **Claude:** `src/api.js` calls Reonic's existing `claude-proxy` Edge Function, so usage shares its daily limit in `reonic_api_usage`. It only accepts the `ahadwen.github.io` origin, so Claude calls fail on a local server.
